# Handoff: Higgsfield dashboard (Elle's install)

Written 2026-10-18. Single-user tool for Elle. Not hosted, not for sharing over a network.

## Run it
- Needs Node. ffmpeg is optional (only for converting MP3/M4A audio uploads to WAV).
- `start.bat` opens the backend (port 4000) and frontend (port 5173) and skips any that are already running.
- Open http://localhost:5173. Sign-in is a local dev screen with no password: Demo Admin, Demo User, Demo Viewer.
  - **Viewer** can look but not generate. **User/Admin** can generate (real spend).
- Branch: `full-dashboard-build`. Everything is committed and pushed except this note.

## What is NOT in the repo (by design)
- **API keys** (Higgsfield, ElevenLabs, Anthropic). Entered in Settings, stored in the local database. Never paste them into chat. A new machine needs its own keys.
- **Project data** (`backend/.data`, git-ignored): Nya's Story, shot board, media library, usage history. A fresh clone starts empty.
- **Local copies of media** (`backend/.data/files`, git-ignored): **Higgsfield deletes uploads and generated files after about a week**, so the dashboard keeps its own copy of every upload and result and re-uploads any expired input before a generation. Anything made before 2026-10-25 has no copy, so expired references from before then must be uploaded again. Back this folder up with the rest of `.data`.
- **Billing**: spend is tracked against whatever key is connected. Elle's key bills Elle's account.

## Spending rules (do not bypass)
- Elle approves every paid generation. Ask first, state the price.
- The dashboard enforces this: cost dialog before any generation, a changed price blocks the run, scheduled workflows that spend are skipped, the Director chat has no generate tool.
- Prices come from Higgsfield's own quote when available, else a saved list. The launch promotion ended 2026-10-18 and the saved list was refreshed on 2026-10-25 (Seedance 2.5 is now $0.2056, $0.4622 and $1.1372 per second at 480p, 720p and 1080p, in every mode). Run Settings, Check prices now and then; Seedance 2.0 reference mode and Kling's saved fallbacks have not been re-based.

## Video effects (added 2026-10-28)
- The **Editing** page adds effects from the Claude "effects" skill (45 of them, by @vibha.in.progress, MIT licence) to a video: gallery, per-effect start, end, text and colour, a single-frame preview (about 20 to 30 seconds), and a full render. Everything runs on this computer and costs nothing. Results are saved in the Media library of the current workspace.
- **Best on a person facing the camera.** The effects follow the face; text can be cut off at the edges on other footage, such as wide AI-generated scenes.
- **Optional label:** a toggle ("Add the dramatization label for the whole video", not one of the 45 effects) adds a solid bar across the bottom with editable text, default `DRAMATIZATION | AI-GENERATED VIDEO`. It is off unless turned on and can be used alone with no effects. On Greene Legal Group the page warns when it is off. Effects are listed alphabetically. The page is called Editing (`/edit`).
- **Setup on a new computer:** clone `https://github.com/Vibha-Ramprakash/claude-video-effects` into `~/.claude/skills/effects`, install Python 3.12 (`winget install Python.Python.3.12`) and ffmpeg, then in that folder run `python -m venv .venv` and `.venv\Scripts\python.exe -m pip install -r requirements.txt`. Set `EFFECTS_DIR` if it lives elsewhere. Uploaded videos and results are in `backend/.data/edit` (back it up with the rest of `.data`).
- Finished edits are served from `/api/edit/files/<random id>.mp4` without a login (the browser's video player cannot send one). The names cannot be guessed, but do not host this publicly without changing that.

- **Review beat by beat:** each video is split into beats (hook, tips, CTA) with a status (draft, in review, changes needed, approved). Ruth edits and submits; only the admin login approves or requests changes, and each line of a change request becomes a checklist item. Editing an approved beat sends it back to draft. Tables: `video_beats` (migration 5).
- **Suggest beats:** the Editing page can propose beats from what is said. Step one transcribes on this computer (the skill's `scripts/words.py`, faster-whisper; the first run installs it and downloads a small speech model, about a minute) and shows the Claude price (Sonnet 5.5, a few cents). Nothing is spent until the button "Confirm and suggest" is pressed. Needs the Anthropic key in Settings. The transcript is kept beside the video as `<id>.words.json`.

- **Captions:** a toggle on the Editing page draws the spoken words on the video, 1 to 6 at a time (default 3), capitals, current word in yellow, above the label bar. Built in `services/captions.ts` as an ASS subtitle file from the transcript and burned in with ffmpeg in the same pass as the label (order: effects, captions, label). Free; uses the same transcript as Suggest beats. Not yet editable: a mis-heard word needs a transcript editor (planned).
- **Caption look and fonts:** colours, italic, size, position, capitals and font are chosen per video; each workspace starts from its own look (Right Girl Media: cream, gold, mauve outline, Trirong; Greene Legal Group: white, red, navy outline). The presets are constants at the top of `frontend/src/pages/Edit.tsx`. **To add a font, drop a .ttf or .otf into the project's `fonts/` folder** (Trirong Medium is there) and restart; it appears in the Font list. The name in the list is the font file's own family name (for example "Trirong Medium"), which is what ffmpeg matches on. Only add fonts whose licence allows it (Google Fonts are OFL).

- **Timeline:** one time axis under the beats with rows Beats (coloured by status, click to review), Titles & Cards, Zoom, Looks (only when used), Captions, and Your cuts (detected). Effects are sorted into rows by name (`ZOOM_FX`, `LOOK_FX` in `Edit.tsx`; everything else is a title or card). Cuts come from ffmpeg scene detection (threshold 0.35, free) and are cached as `<id>.cuts.json` beside the video; the Captions row shows where speech runs once the video has been transcribed.

- **Numbered drafts:** every render is kept as a draft (v1, v2, ...) in the video's record (`drafts`), with who rendered it, when, the settings used, and a plain-words list of what changed from the draft before (`services/drafts.ts`). Under "Drafts" on the Editing page: Watch, Compare (tick two to play side by side), Submit for review (anyone on the team), Approve or Request changes (admin only; the note shows on the draft). Statuses match beats: draft, in review, changes needed, approved. The edits list shows the latest draft and its status. Drafts made before this change do not exist; the first render after it becomes v1.

- **Transcript editor:** the "Transcript" card on the Editing page shows the spoken words in lines with their start times. Each word is editable; there is find and replace (whole words, any case), add a word, join two words, delete, Save, Discard, and "Back to the original". The first save keeps the transcriber's version as `<id>.words.original.json`; the corrected one replaces `<id>.words.json`, so captions, the Captions timeline row and Suggest beats all use it. Timing is not editable (new words are placed in the gap). Drafts already rendered keep their old captions. A video that was never transcribed has a "Listen to the video" button (free). Routes: GET/PUT `/videos/:id/words`, POST `/videos/:id/transcribe`, POST `/videos/:id/words/reset`. Not yet run in the browser.
- **Video beside the transcript:** the Transcript card has a player (sticky on the right). Click a line's time to play from there, click a word to jump to it, and the word being said lights up. Uploaded source videos are played through a signed link (`GET /videos/:id/stream-url` returns `/api/edit/source/:id?exp=&sig=`), HMAC-signed with a secret made when the server starts and valid 2 hours, so source videos are NOT open like the result files; a server restart just means the page asks for a new link (`services/sourceLinks.ts`).

- **Transcriber setup gotcha (found 2026-10-29):** faster-whisper 1.2.1 fails with `open() got an unexpected keyword argument 'metadata_errors'` if the effects skill's venv has `av` 19.x. Fix: `.venv\Scripts\python.exe -m pip install "av==15.1.0"` in `~/.claude/skills/effects`. The first transcription also downloads the Whisper "base" model from Hugging Face (needs internet once).
- **Browser test pass (2026-10-29, Demo Admin, a generated 11 second spoken clip):** transcribe, find and replace, save (original kept), restore original, player play/seek/word highlight, captions render with corrected spelling in Trirong with the Right Girl Media colours, drafts v1/v2, change list, compare, submit, request changes, approve all worked. Not tested: the Team (Demo User) login being refused on approve, a real client video, Suggest beats with a real Anthropic key, the Greene Legal Group workspace look.

## Content Vault (added 2026-10-30)
The "Vault" page (`/vault`, `routes/vault.ts`, `services/vault.ts`, `pages/Vault.tsx`, migration 6 `vault_clips` and `vault_reels`) organizes raw footage and plans reels from it.
- **Adding footage (free):** admin only: "Read folder" takes a full path on this computer and reads every MP4/MOV/M4V/WebM (and, since 2026-11-01, JPG/PNG/WebP/HEIC photo) in it and its sub-folders (up to 5000; dot-folders skipped; files stay where they are and are never deleted). Anyone on the Team: "Upload clips" (several at once, 500 MB each, saved to `backend/.data/vault/clips`). For each clip it reads length, size, played orientation, when it was filmed (iPhone local time first, then the file's creation_time, then the file's modified time), whether it has sound (average loudness above -35 dB) and a thumbnail (`.data/vault/thumbs`). A copy of a clip already there (same size plus first and last 64 KB) is kept but marked a duplicate and not counted.
- **Sorting (paid, price first):** Claude Haiku 5.5 looks at 3 frames per clip and picks one of the folders in `VAULT_FOLDERS` (Talking head, Desk, Studio, Close-ups, On the go, Outdoors, Events, Food & drink, Screen recording, Other), 3 to 6 tags and a one-line description. `POST /vault/sort {approved:false}` is free and returns the price and whether the key is missing; `{approved:true}` starts it. One run does at most the newest 500 unsorted clips and stops at the quoted maximum. About $0.00016 a clip, so roughly 7 cents for 400. Filing a clip by hand counts as sorted. The page shows the ball of unsorted thumbnails and folder boxes that fill as clips are sorted.
- **Days:** clips group by the day filmed ("By day" tab). A day with 3 or more clips can be sent to reel planning.
- **Reel ideas (paid, price first):** Claude Sonnet 5.5 plans up to 8 reels from the sorted clips: "vlog" (one day's clips in the order filmed) and "topic" (any days, one hook). Each beat names a real clip; invented clip ids and reels with fewer than 3 real beats are dropped; a beat never runs longer than its clip. Voice is chosen by workspace name (GLG gets the compliance rules: no case results or amounts, DRAMATIZATION label on anything staged). Saved in `vault_reels` with Save, Mark used, Delete.
- **Playing a clip:** signed link like source videos (`/api/vault/clip/:id?exp=&sig=`, `signVaultLink`; a vault link never opens an edit video or the reverse).
- **Tested:** 17 new tests (`tests/vault.test.ts`, with real ffmpeg clips); browser pass against a mock of the Anthropic API (`ANTHROPIC_BASE_URL`) with 22 clips over 5 days: scan, duplicate, ball, sorting progress, folder boxes, By day, reel planning, clip player. NOT tested with a real Anthropic key (image requests and the reel prompt have only been run against the mock), nor with a real iPhone export, nor with hundreds of clips.
- **Not built yet:** Folder list is a code constant. Sorting is one click with no price step (Elle's choice, 2026-10-30); reel planning still shows its price first. (Photos and the on-disk folders were added 2026-11-01, below.)

### Photos, the sorting animation and real folders on the computer (added 2026-11-01)
Built from a reference video Elle liked (a "Claude turns my camera roll chaos into organized folders" sorter): live counters, a ball of tiles flying into folder cards, and files ending up in real folders. She asked for the animation, photos and videos together, and the sorting done on the computer.
- **Photos (migration 7, `vault_clips.kind` 'video'|'photo', default 'video'):** the scan reads JPG, JPEG, PNG, WebP and HEIC as well as videos; uploads accept the same (`UPLOAD_TYPES`). A photo's day is its EXIF date when the camera wrote one (read through ffprobe frame tags, `exifTime`), else the file's modified time. No length or sound. Sorting sends one picture instead of three (`sortTokens`), so the quote is cheaper for photos; the prompt gained "Selfies & portraits" and "Screenshots" folders. Photos are filed and searchable (Videos/Photos filter chips) but **never offered to reel planning or B-roll** (`catalogFor` is video-only; the stats carry `videos`, `photos`, `sortedVideos`, and each day carries `videos`). HEIC is accepted but depends on this ffmpeg build decoding it; untested.
- **The animation** (`frontend/src/components/SortStage.tsx`, replacing the old ball card): a cream-to-pink panel with a serif title and mauve accents. The sort job keeps a `log` of `{id, folder}` as each file is filed; the page polls `GET /vault/jobs/:id?since=N` (new entries only, 700 ms) and flies one tile from the ball to that folder's card per entry (Web Animations), thinning the ball in step with progress. Counters (Files, Sorted, Waiting, Folders) tick as tiles land. A reduced-motion setting skips the flight. Card contents are re-read from the server once nothing is in the air, so the final picture is the real one. Shared types and the `useJob` hook moved to `frontend/src/lib/vault.ts`.
- **Real folders** (admin only; `POST /vault/organize`, `GET /vault/organize/last`, `POST /vault/organize/:id/undo`; `OrganizeCard` on the Vault page): puts the sorted files that came from a folder on this computer into `<chosen folder>\Photos\<topic>\` and `\Videos\<topic>\`. Step 1 (`approved:false`) is free and lists the counts and what is left alone (unsorted files, duplicates; uploads stay in the Vault). **Copy** (default) leaves originals alone and a second run makes no twin (same size plus first and last 64 KB means already there); **Move** takes files out of their old folders, points the Vault at the new place, and writes `.data/vault/moves/<jobId>.json` so "Put them back" works even after a reload or restart (it only moves a file back if the new place still holds it and the old place is free, then removes the empty folders it made). Nothing is ever overwritten (`name (2).ext`); a whole drive is refused as a destination.
- **Bug found and fixed on the way:** ffmpeg gives no picture at all for a JPEG when told to seek to 0.00 s, so photos had no thumbnails and could not have been sorted; `frameAt` now skips the seek for photos (test asserts every photo has a thumbnail).

## Study Session (added 2026-11-02)
Section 2 of Elle's agency blueprint ("a dedicated terminal to upload and feed reference videos to Claude to analyze and use for future content generation"). Page `/study` (`pages/Study.tsx`, nav item "Study"), `routes/study.ts`, `services/study.ts`, migration 8 (`study_refs`, plus `vault_reels.modeled_on`).
- **Adding (free):** upload an MP4/MOV/WebM reel (up to 3 minutes, 500 MB; saved to `backend/.data/study`, `STUDY_DIR`). It is read here: length, size, where the picture cuts (ffmpeg scene detection, `findCuts`, threshold 0.3), pace worked out in code (`pacingOf`: shots, average shot, cuts per 10 s, first cut), and a poster. The same file uploaded twice is caught (fingerprint). No URL download: she uploads the file and may paste the original link as a note (`source_url`, never fetched).
- **Studying (paid, price first):** `POST /study/:id/analyse {approved}`. Claude Sonnet 5.5 sees 10 frames (512 px, at known seconds), the software's cut/pace numbers, her "what I like about it" note and the spoken words. The words come from the effects skill's `words.py` (faster-whisper) only if that engine is set up; otherwise the prompt says there is no transcript and the study goes ahead on pictures alone. Transcribing takes noticeable time (about 15 s for an 8 s silent clip on this machine, model load). Result stored on the row (`analysis` jsonb: summary, format, hook {said, shown, technique, why}, structure beats with seconds, pacing, on-screen text, audio, CTA, steal, avoid, a fill-in-the-blank skeleton). Prompt tells Claude to say when something is not visible (music) rather than guess. Page: timeline buttons seek the player.
- **Using it, two ways (both price first):** (1) **Write your own** (`POST /study/:id/script {topic, approved}`): Sonnet writes a script (hook, beats with say / on-screen / shot / seconds, caption, a note on what it kept) on the studied structure, in the workspace's voice using the same copied skill rules as captions (`voiceRules`; the GLG workspace gets the legal rules note), and `findTells` flags machine-sounding lines on the card instead of hiding them. Up to 20 scripts kept per study; Copy gives plain text. Never reuse the reference's words. (2) **Model Vault reels on it:** on the Vault's Reel ideas tab, tick up to 3 studied reels under "Model them on"; `POST /vault/reels/suggest` takes `studyIds`, the route builds the notes (`playbookFor`) and `suggestReels` appends them to the prompt ("borrow structure, never wording or subject"), the quote includes the extra tokens, and the saved reels show "Modeled on ...".
- **Tested:** `tests/study.test.ts` (12 tests, real ffmpeg: parsers, pace, upload, cut detection, duplicate and bad-file refusals, signed player link, quote spends nothing, analysis sends 10 images and the software facts, script quote then approve with the studied structure in the prompt, em-dash flagged, refusal before a study, Vault reels modeled on a study incl. cost and label, delete removes the file). Browser pass on an isolated stack with the Anthropic mock: upload, list, price then approve, analysis display, timeline, skeleton, script quote/approve/display, phone width (no sideways scroll). 264 backend tests, both type-checks and the frontend build pass.
- **NOT tested:** a real Anthropic key (does the analysis say anything true about a real reel; frames are 512 px, so small on-screen text may be missed), a real reference reel with speech (only silent test clips were run through the real transcriber), a 3-minute video, the Vault "Model them on" checkboxes in the browser (covered through the API only), the GLG workspace look. Study rows are per workspace but cost totals are not.
- **From a link (added the same day, migration 9 `study_refs.meta`):** `POST /study/from-link {url}` runs yt-dlp (must be on PATH, or set `YTDLP_PATH`) to download the reel to `.data/study`, and keeps the caption, uploader, post date and the public likes/comments/views as they were then. The download is free, and **pasting a link also studies the reel straight away** (Elle's choice: no price step, about 2 cents, cost shown after; a reel already studied is not paid for again; if the study fails the reel stays saved and the error is shown). Uploaded files still wait for "See the price". Only https links on instagram.com, tiktok.com, youtube.com/youtu.be, facebook.com/fb.watch are accepted (`checkLink`, also what keeps the server from being pointed at anything else); the URL goes after `--` and no shell is used. No cookies or logins are used, so private posts and login-walled ones fail with "upload the file instead". Up to 3 minutes. ## Metrics (added 2026-11-02)
Section 5 of the blueprint. Page `/metrics` (`pages/Metrics.tsx`), `routes/metrics.ts`, `services/metrics.ts`, migration 10 (`ig_accounts`, `ig_posts`, `ig_snapshots`, `ig_account_days`). Elle chose real Instagram insights over reading public post links.
- **How it connects:** "Instagram API with Instagram Login" (`graph.instagram.com`, `config.instagramGraphBase`, env `INSTAGRAM_GRAPH_BASE` for tests). One access token per Instagram Business/Creator account, pasted by an admin (`POST /metrics/accounts`, admin only), checked against `/me`, stored encrypted (`encryptSecret`, only the last 4 shown, never returned to the page, scrubbed from error messages). Permissions: `instagram_business_basic` and `instagram_business_manage_insights`. The token is refreshed with `ig_refresh_token` on connect and whenever its expiry is unknown or under 14 days away (Instagram refuses tokens under a day old; that is ignored). A dead token (Graph code 190) sets `last_error` and the page says to connect again.
- **What a sync reads (free; anyone on the Team can refresh):** the profile (followers, follows), the newest 40 posts (up to 100) with likes/comments counts, then each post's insights: reels get reach, views, likes, comments, saved, shares, reposts, total_interactions, ig_reels_avg_watch_time, ig_reels_video_view_total_time; other posts get the same minus the watch times plus follows and profile_visits. Metric names are from Meta's docs (checked 2026-11-02) and they change: if Instagram refuses a metric the sync asks for each one separately, remembers the refused ones for the rest of that sync, and keeps going (`withoutInsights` in the response; the page says some numbers are not shared). Account reach per day for 28 days is best effort. Stories are not read.
- **Growth:** every sync stores a snapshot per post only when its numbers changed, so a post's growth line fills in as the team refreshes; followers get one row a day, so the follower line starts when the account is connected (Instagram does not give past follower counts). Nothing syncs by itself yet: it is the Refresh button. Engagement is computed here: (likes + comments + saves + shares) / reach.

## B-roll from the Vault (added 2026-10-30)
A Vault clip shown over part of an edit while the edit's own sound carries on. Stored in the edit's plan as `broll: [{clipId, start, end, from}]` (zod `brollSchema`, max 40), saved by the editor's autosave like effects and captions, and kept in each draft's plan (`describeChanges` says "Added B-roll (n clips)", "Changed the B-roll", "Removed the B-roll").
- **Render:** `services/broll.ts` `composeBroll` lays the cutaways in first (ffmpeg `overlay` with `enable='between(t,start,end)'`; each clip is scaled and cropped to fill the video's picture, looped if shorter than its cutaway, video sound copied through), then effects, captions and the label run on the result. B-roll alone is enough to render. A clip removed from the Vault gives a plain error naming the problem. `run()` moved to `services/exec.ts` (effects.ts imports it) to avoid an import cycle.
- **Three ways in** (Editing page, "B-roll" card and a "B-roll" timeline row): "Add a clip" (picker over the Vault, lands on the selected beat), "Suggest from my Vault" (`POST /edit/videos/:id/broll/suggest`, Claude Haiku 5.5, text only, one click, about a cent, cost shown after; needs beats and sorted clips; one clip once, 1 to 4.5 s, inside its beat; nothing is saved by the server, the page adds the picks and autosaves), and on a Vault reel "Use as B-roll in an edit" (`POST /vault/reels/:id/to-edit {videoId}`: one cutaway per reel beat spread across the video's beats or evenly along it, replaces existing B-roll, then opens the edit via `/edit?video=<id>`). Placement and parsing are pure functions (`placeReelBroll`, `parseBrollPicks`).
- **Not built:** the preview frame ignores B-roll (check by rendering, which is free); cutaway timing is typed in seconds, not dragged; no crossfade; the clip's own sound is never used; Drafts compare does not list B-roll clips by name.
- **Tested:** `tests/broll.test.ts` (real ffmpeg renders checked by sampling the picture before, during and after a cutaway; short-clip loop; reel to edit through the API); browser pass with the Anthropic mock: reel to edit, timeline row, suggest (2 of 4 mock picks kept), render of B-roll alone, output frames and sound checked.
